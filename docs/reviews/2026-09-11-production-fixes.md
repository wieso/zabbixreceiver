# Исправления production review — 11 сентября 2026

Все шесть замечаний из [исходного ревью](2026-09-11-production-review.md) устранены в рабочей копии. Повторное независимое ревью исправлений не выявило дополнительных actionable-дефектов. Коммиты, PR и релиз не опубликованы.

## Изменения

| Замечание | Исправление |
| --- | --- |
| Уязвимый toolchain | Минимальная версия обоих модулей — Go 1.26.8; CI, release и Docker используют 1.26.8. `make vulncheck` проверяет оба модуля. Скрипт выпуска сканирует каждый целевой бинарник до упаковки; CI сканирует также бинарник из контейнера. |
| Секреты URL в логах | Удаляются userinfo, query и fragment из `url.Error`; санитизируются обёртки и URL в текстовых ошибках malformed Location. Сохраняются cancellation, timeout и доступ к санитизированному `url.Error` через `errors.As`. Поддержка query-параметров в реальных запросах сохранена. |
| Обход лимита deflate | После конца decoded-потока проверяется чтение оставшегося HTTP-тела. Учитываются sticky-ошибки MaxBytesReader, даже если декомпрессор проглотил их при read-ahead. Превышение лимита даёт 413 без передачи downstream; поздняя ошибка чтения — 400. |
| Два API Pod при rollout | Одиночный API Deployment переведён на Recreate. Убраны maxSurge/maxUnavailable. Документация описывает перерыв сбора и границы этого решения. |
| Противоречия scaling-документации | Исправлены поддержка сжатия, пропуск невалидных строк, момент увеличения emitted_points; добавлена память декодеров и оговорка о версии исторических измерений. |
| Grafana отсутствует после быстрого старта | Grafana включена в `make demo-up`; `make demo-verify` проверяет свежие метрики и отдельно здоровье Grafana/наличие ожидаемого дашборда. |

Дополнительно исправлена проверка платформы в скрипте упаковки: Linux-бинарники запускаются непосредственно только на соответствующей Linux-платформе.

## Принятые компромиссы

На два уточнения о предпочтениях к моменту реализации ответ не поступил. После ожидания выбраны и озвучены рекомендованные обратимые настройки; это не утверждение о полученном согласовании SLO:

- **Recreate:** простой rollout без параллельного владельца API-шарда, с перерывом на остановку, старт и discovery. Это не HA и не fencing при сетевом разделении/принудительном удалении Pod.
- **Сохранение таблицы символов:** сборка с `-w`, без `-s`. Локально Linux amd64 файл вырос примерно с 35 до 40 МиБ. Это позволяет govulncheck проверить присутствующие символы поставляемого файла. При удалении таблицы сканер консервативно сообщил об уязвимостях неиспользуемых SSH/OpenPGP-пакетов из списка модулей; с таблицей символов проверка того же проекта проходит. Уязвимости не добавлены в исключения и сканирование не отключено.

В корневом модуле govulncheck указывает три записи в зависимостях без импортируемых уязвимых пакетов/достижимых вызовов; для отдельного receiver выдаёт `No vulnerabilities found`. Положительный результат означает отсутствие известных достижимых уязвимостей по использованной базе, а не отсутствие любых возможных дефектов.

Проверочные архивы имеют техническую версию `v0.0.0` и находятся в `dist/`; они не являются опубликованным релизом. Предыдущие локальные архивы сохранены в каталоге `/tmp/zabbix-release-backup.*`. Финальный проверочный образ: `zabbix-otel-collector:production-review`; этот же образ установлен в локальный демо-стенд как `zabbix-otel-collector:local`.

## Граница результата

Подтверждены исправления выявленных дефектов, сборка и перечисленные проверки. Не проводились развёртывание в Kubernetes/systemd, длительная нагрузочная приёмка и подтверждение RPO/RTO на целевой инфраструктуре. Исходные документированные ограничения сохраняются: API читает lastvalue, HTTP 200 не гарантирует долговременную запись, discovery ограничен 8 MiB, нет встроенного HA/устойчивого входного журнала. Если эти свойства не удовлетворяют требованиям эксплуатации, понадобятся отдельные архитектурные изменения.
