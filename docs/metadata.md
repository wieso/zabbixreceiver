# Метаданные Zabbix в лейблах

[Настройка приёмника](configuration.md) · [Пример Streaming с API](../configs/otelcol-streaming-enriched.yaml)

Метаданные передаются как строковые атрибуты каждой точки OpenTelemetry. `prometheusremotewrite` преобразует их в лейблы. Релейблинг для этого не требуется; конфигурация exporter и VM не меняется.

```yaml
receivers:
  zabbix:
    metadata:
      enabled: true
      host_groups_format: both
      inherited_host_tags: true
      inventory_fields: [os, location]
```

`enabled` и `inherited_host_tags` включены по умолчанию. `inventory_fields` по умолчанию пуст: inventory не запрашивается. Здесь `os` и `location` — пример явно выбранных полей, а не обязательный набор. Возвращённые API поля вне списка не копируются. Имена полей должны соответствовать `[a-z][a-z0-9_]*`; существование поля проверяет Zabbix API.

`metadata.enabled: false` отключает новые атрибуты и дополнительные параметры API; сохраняются прежние идентификаторы и `prom.const_labels`. Это также режим совместимости для старых серверов без API тегов. API метаданных рассчитан на Zabbix 6.0 и новее.

## Поля

| Источник | Лейбл | Polling | Streaming без API |
| --- | --- | --- | --- |
| Техническое имя хоста | `host` | Да | Да |
| ID хоста | `hostid` | Да | Нет |
| ID элемента | `itemid` | Да | Да |
| Ключ элемента | `item_key` | Да | Нет |
| Видимое имя хоста | `host_name` | `host.get.name` | `host.name` |
| Название элемента | `item_name` | `item.get.name` | `name` |
| Тип значения | `value_type` | `value_type` | `type` |
| Единицы измерения | `item_units` | `units`, если непустые | Нет |
| Теги элемента | `item_tag_<ключ>` | `selectTags` | `item_tags` |
| Собственные теги хоста | `host_tag_<ключ>` | `selectTags` | Нет |
| Теги родительских шаблонов хоста | `host_inherited_tag_<ключ>` | `selectInheritedTags` | Нет |
| Группа хоста | `host_groups="Linux, Production"` | `selectHostGroups` / `selectGroups` | `groups` |
| Выбранные поля inventory | `inventory_<ключ>` | `selectInventory` | Нет |

Теги хоста, шаблонов хоста и элемента не перезаписывают друг друга. Для item tags сохраняется результат `item.get.selectTags`: происхождение тега от шаблона/LLD отдельно не вычисляется. Макросы приёмник не раскрывает — передаёт строку, полученную от Zabbix.

Метаданные источника записываются после `const_labels` и имеют приоритет при совпадении имени лейбла. Для собственных постоянных лейблов используйте имена вне семейств `item_*`, `host_*`, `inventory_*`, `value_type`.

Метаданные не меняют тип Gauge, значение и timestamp. Единицы передаются атрибутом, а не `metric.unit`, чтобы exporter не добавлял новый суффикс имени. Название элемента остаётся также в description.

## Имена и значения тегов

Ключи тегов и inventory приводятся к lowercase snake_case тем же правилом, что и имена метрик: `%` → `percent`, `°` → `degree`, `+` → `plus`, `&` → `and`; остальная пунктуация, включая двоеточие `:` и слеш `/`, и символы вне ASCII становятся `_`. Повторные разделители схлопываются, начальные и конечные удаляются. Hex-кодирования и зарезервированного префикса `encoded_` нет.

| Исходный ключ | Суффикс лейбла |
| --- | --- |
| `application` | `application` |
| `a.b`, `a-b`, `a_b`, `a:b`, `a/b` | `a_b` |
| `CPU:://Usage` | `cpu_usage` |
| `CPUUsage` | `cpu_usage` |
| `encoded_612e62` | `encoded_612e62` |
| пустой ключ или только разделители | `unnamed` |

Одиночное значение передаётся буквально, включая пустую строку, Unicode и строки вида `["x"]`, `/var/log` или `https://host:443`. Двоеточия и слеши в значениях не заменяются. JSON-обёрток нет. Пустой лейбл downstream может опустить; receiver не подменяет его искусственным значением.

Если несколько тегов дают один нормализованный ключ, значения сортируются, точные дубликаты удаляются и результат соединяется через `, `: `api, web`. Это читаемое представление, а не обратимое кодирование: литерал `api, web` неотличим от двух значений. Такое же правило действует при совпадениях ключей inventory.

Названия групп передаются в одном лейбле `host_groups` без нормализации: сохраняются регистр, пробелы, Unicode и пунктуация. Названия сортируются, точные дубликаты удаляются, значения соединяются через `, `; например, `host_groups="Linux, Production"`. При отсутствии групп лейбл не добавляется. Это также не обратимое кодирование: запятая в исходном названии не экранируется. Порядок исходных тегов, групп и inventory не влияет на результат.

Переход со старого формата меняет серии: `zabbix_item_tag_app` становится `item_tag_app`, JSON-массивы заменяются обычными значениями. Обновите запросы и панели; ранее сохранённые серии не переименовываются. Настраиваемый `prom.prefix` относится только к именам метрик и нормализуется вместе с их исходным именем. Ресивер не добавляет `zabbix_` к генерируемым лейблам; пользовательские `prom.const_labels` передаются как заданы.

В v0.3.1 и v0.3.2 группы передавались только как `host_groups`. С v0.3.3 формат выбирается настройкой `metadata.host_groups_format`:

| Значение | Лейблы |
| --- | --- |
| `names` | `host_groups="Linux, Production"` |
| `flags` | `host_group_linux="true"`, `host_group_production="true"` |
| `both` (по умолчанию) | Оба представления одновременно |

Настройка применяется к API и Streaming, включая API-обогащение. В `flags` и `both` суффиксы `host_group_*` нормализуются по правилам ключей тегов; совпавшие ключи дают один лейбл со строковым значением `"true"`. `host_groups` сохраняет исходные названия. При отсутствии групп ни одно представление не добавляется. `metadata.enabled: false` отключает оба представления. Неизвестное значение формата вызывает ошибку конфигурации.

По умолчанию передаются оба представления (`both`), как в примере выше. Чтобы оставить только список названий, установите `host_groups_format: names`. В v0.3.3 значением по умолчанию было `names`; начиная с v0.3.4 — `both`. Смена формата меняет набор лейблов и создаёт новые серии; исторические серии не переименовываются. Пользовательские `prom.const_labels` продолжают передаваться как заданы, поэтому не используйте зарезервированные имена `host_groups` и `host_group_*` для постоянных лейблов.

## API-обогащение Streaming

```yaml
receivers:
  zabbix:
    mode: streaming
    streaming:
      endpoint: 0.0.0.0:8081
      token: ${env:ZABBIX_STREAM_TOKEN}
      enrich_with_api: true
    metadata:
      enabled: true
      inherited_host_tags: true
      inventory_fields: [os, location]
    zabbix:
      url: ${env:ZABBIX_URL}
      token: ${env:ZABBIX_TOKEN}
    schedule:
      jobs:
        discover: {enabled: true, run_on_start: true, interval: 5m, timeout: 60s}
        values: {enabled: false}
```

`enrich_with_api` выключен по умолчанию. При включении обязательны `metadata.enabled`, API URL/токен и задача `discover`. Действуют обычные настройки timeout, фильтров, лимитов и переопределения окружения API. Задача `values` не запускается даже при `enabled: true`: значения поступают только из streaming.

Discovery обновляет атомарный снимок и индекс по `itemid`. Обработчик берёт один снимок на весь HTTP-запрос. Поиск элемента не копирует весь кэш и не обращается к API. Срезы тегов и карты inventory копируются на границах снимка, поэтому параллельное обновление не меняет метаданные выполняющегося запроса.

Имя метрики формируется из ключа API, как при polling; без обогащения доступно только название из payload. Из API добавляются `hostid`, `item_key`, теги хоста/шаблонов, units, inventory. Непустое `host.name` и обязательные `name`/`type` из payload имеют приоритет над кэшем. Отсутствующие `item_tags` и `groups` дополняются из кэша. Явные пустые массивы `[]` очищают соответствующие данные для этой записи; `null` трактуется как отсутствие.

До первого успешного discovery и при неизвестном `itemid` числовой запрос получает **503**, целиком, без частичной передачи. Настройте повторные попытки Zabbix Connector с учётом интервала discovery. Фильтры и `max_metrics_per_host` ограничивают также кэш обогащения: все отправляемые элементы должны попадать в выбранный набор, иначе запросы с ними будут получать 503.

Ошибка обновления сохраняет последний успешный снимок; TTL-просрочки нет. Успешный discovery удаляет из кэша исчезнувшие/отфильтрованные элементы. Возраст метаданных виден по `otelcol_receiver_zabbix_discover_last_success_timestamp`, ошибки — по `otelcol_receiver_zabbix_discover_errors`. Обычные гарантии доставки streaming не меняются: 200 подтверждает приём следующим компонентом Collector, а не долговременную запись в VM.

## Совместимость и ограничения

Современный API групп использует `selectHostGroups`. При явной ошибке `unexpected parameter "selectHostGroups"` или успешном ответе с хостами без свойства `hostgroups` клиент повторяет запрос с `selectGroups`, используемым Zabbix 6.0, и запоминает успешно выбранный вариант. Прочие ошибки API не приводят к отключению метаданных или обходу валидации. `inherited_host_tags: false` исключает запрос и передачу наследуемых тегов.

Добавление лейблов создаёт новые серии; ранее сохранённые серии не дополняются. Изменение метаданных также меняет идентичность серии. Receiver не обрезает имена или значения; лимиты числа/длины лейблов принимающего хранилища нужно учитывать отдельно, особенно при большом числе тегов/групп. Предел ответа API остаётся 8 MiB: превышение вызывает ошибку discovery и сохранение предыдущего снимка.

Это передача перечисленных метаданных, а не выгрузка всей базы Zabbix: текстовые значения, события, история между polling-опросами, макросы и произвольные поля конфигурации не добавляются в лейблы.
