# Метаданные Zabbix в лейблах

[Настройка приёмника](configuration.md) · [Пример Streaming с API](../configs/otelcol-streaming-enriched.yaml)

Метаданные передаются как строковые атрибуты каждой точки OpenTelemetry. `prometheusremotewrite` преобразует их в лейблы. Релейблинг для этого не требуется; конфигурация exporter и VM не меняется.

```yaml
receivers:
  zabbix:
    metadata:
      enabled: true
      inherited_host_tags: true
      inventory_fields: [os, location]
```

`enabled` и `inherited_host_tags` включены по умолчанию. `inventory_fields` по умолчанию пуст: inventory не запрашивается. Здесь `os` и `location` — пример явно выбранных полей, а не обязательный набор. Возвращённые API поля вне списка не копируются. Имена полей должны соответствовать `[a-z][a-z0-9_]*`; существование поля проверяет Zabbix API.

`metadata.enabled: false` отключает новые атрибуты и дополнительные параметры API; сохраняются прежние идентификаторы и `prom.const_labels`. Это также режим совместимости для старых серверов без API тегов. API метаданных рассчитан на Zabbix 6.0 и новее.

## Поля

| Источник | Лейбл | Polling | Streaming без API |
| --- | --- | --- | --- |
| Техническое имя хоста | `host` | Да | Да |
| ID хоста | `hostid` | Да | Нет |
| ID элемента | `itemid` | Да | Да |
| Ключ элемента | `item_key` | Да | Нет |
| Видимое имя хоста | `zabbix_host_name` | `host.get.name` | `host.name` |
| Название элемента | `zabbix_item_name` | `item.get.name` | `name` |
| Тип значения | `zabbix_value_type` | `value_type` | `type` |
| Единицы измерения | `zabbix_item_units` | `units`, если непустые | Нет |
| Теги элемента | `zabbix_item_tag_<ключ>` | `selectTags` | `item_tags` |
| Собственные теги хоста | `zabbix_host_tag_<ключ>` | `selectTags` | Нет |
| Теги родительских шаблонов хоста | `zabbix_host_inherited_tag_<ключ>` | `selectInheritedTags` | Нет |
| Группа хоста | `zabbix_host_group_<ключ>="true"` | `selectHostGroups` / `selectGroups` | `groups` |
| Выбранные поля inventory | `zabbix_inventory_<ключ>` | `selectInventory` | Нет |

Теги хоста, шаблонов хоста и элемента не перезаписывают друг друга. Для item tags сохраняется результат `item.get.selectTags`: происхождение тега от шаблона/LLD отдельно не вычисляется. Макросы приёмник не раскрывает — передаёт строку, полученную от Zabbix.

Метаданные источника записываются после `const_labels` и имеют приоритет при совпадении имени лейбла. Для собственных постоянных лейблов используйте имена вне семейств `zabbix_item_*`, `zabbix_host_*`, `zabbix_inventory_*`, `zabbix_value_type`.

Имена метрик, их тип Gauge, значение и timestamp не меняются. Единицы передаются атрибутом, а не `metric.unit`, чтобы exporter не добавлял новый суффикс имени. Название элемента остаётся также в description.

## Имена и значения тегов

Имена, состоящие из ASCII-букв, цифр и `_`, сохраняются. Исключения: пустое имя и зарезервированный префикс `encoded_`. Все остальные имена кодируются как `encoded_` + hex от полных UTF-8 байтов исходного имени. Это исключает слияние `a.b`, `a-b` и `a_b` после нормализации exporter. Правило одинаково для тегов, групп и ключей inventory.

| Исходный ключ | Суффикс лейбла |
| --- | --- |
| `application` | `application` |
| `a_b` | `a_b` |
| `a.b` | `encoded_612e62` |
| `encoded_612e62` | `encoded_656e636f6465645f363132653632` |
| пустая строка | `encoded_` |

Для каждого имени тега значения сортируются и точные дубликаты удаляются:

- Одно непустое значение передаётся как обычная строка: `web`.
- Несколько значений — компактный JSON-массив: `["api","web"]`.
- Пустое значение — JSON-массив `[""]`, чтобы exporter не отбросил лейбл.
- Единственное значение, начинающееся с `[`, также оборачивается в JSON-массив. Поэтому литерал `["api","web"]` можно отличить от двух значений.

Значение лейбла, начинающееся с `[`, следует декодировать как JSON-массив; остальные значения — одиночные строки. Выбранные значения inventory используют такое же кодирование. Пустой набор тегов не создаёт лейблов. Порядок тегов и групп в ответе Zabbix не меняет набор лейблов.

## API-обогащение Streaming

```yaml
receivers:
  zabbix:
    mode: streaming
    streaming:
      endpoint: 0.0.0.0:8081
      token: ${env:ZABBIX_STREAM_TOKEN}
      enrich_with_api: true
    metadata:
      enabled: true
      inherited_host_tags: true
      inventory_fields: [os, location]
    zabbix:
      url: ${env:ZABBIX_URL}
      token: ${env:ZABBIX_TOKEN}
    schedule:
      jobs:
        discover: {enabled: true, run_on_start: true, interval: 5m, timeout: 60s}
        values: {enabled: false}
```

`enrich_with_api` выключен по умолчанию. При включении обязательны `metadata.enabled`, API URL/токен и задача `discover`. Действуют обычные настройки timeout, фильтров, лимитов и переопределения окружения API. Задача `values` не запускается даже при `enabled: true`: значения поступают только из streaming.

Discovery обновляет атомарный снимок и индекс по `itemid`. Обработчик берёт один снимок на весь HTTP-запрос. Поиск элемента не копирует весь кэш и не обращается к API. Срезы тегов и карты inventory копируются на границах снимка, поэтому параллельное обновление не меняет метаданные выполняющегося запроса.

Из API добавляются `hostid`, `item_key`, теги хоста/шаблонов, units, inventory. Непустое `host.name` и обязательные `name`/`type` из payload имеют приоритет над кэшем. Отсутствующие `item_tags` и `groups` дополняются из кэша. Явные пустые массивы `[]` очищают соответствующие данные для этой записи; `null` трактуется как отсутствие.

До первого успешного discovery и при неизвестном `itemid` числовой запрос получает **503**, целиком, без частичной передачи. Настройте повторные попытки Zabbix Connector с учётом интервала discovery. Фильтры и `max_metrics_per_host` ограничивают также кэш обогащения: все отправляемые элементы должны попадать в выбранный набор, иначе запросы с ними будут получать 503.

Ошибка обновления сохраняет последний успешный снимок; TTL-просрочки нет. Успешный discovery удаляет из кэша исчезнувшие/отфильтрованные элементы. Возраст метаданных виден по `otelcol_receiver_zabbix_discover_last_success_timestamp`, ошибки — по `otelcol_receiver_zabbix_discover_errors`. Обычные гарантии доставки streaming не меняются: 200 подтверждает приём следующим компонентом Collector, а не долговременную запись в VM.

## Совместимость и ограничения

Современный API групп использует `selectHostGroups`. При явной ошибке `unexpected parameter "selectHostGroups"` или успешном ответе с хостами без свойства `hostgroups` клиент повторяет запрос с `selectGroups`, используемым Zabbix 6.0, и запоминает успешно выбранный вариант. Прочие ошибки API не приводят к отключению метаданных или обходу валидации. `inherited_host_tags: false` исключает запрос и передачу наследуемых тегов.

Добавление лейблов создаёт новые серии; ранее сохранённые серии не дополняются. Изменение метаданных также меняет идентичность серии. Receiver не обрезает имена или значения; лимиты числа/длины лейблов принимающего хранилища нужно учитывать отдельно, особенно при длинных кодированных именах и большом числе тегов/групп. Предел ответа API остаётся 8 MiB: превышение вызывает ошибку discovery и сохранение предыдущего снимка.

Это передача перечисленных метаданных, а не выгрузка всей базы Zabbix: текстовые значения, события, история между polling-опросами, макросы и произвольные поля конфигурации не добавляются в лейблы.
