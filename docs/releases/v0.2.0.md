# v0.2.0 — Streaming, метаданные и наблюдаемость

Статус: подготовлено к выпуску; публикация тегов и артефактов выполняется после объединения PR и успешных проверок по [порядку выпуска](../development.md).

## Изменения

- Добавлен HTTP Streaming числовой истории Zabbix, включая сжатые запросы, ограничения размера тела и опциональное обогащение метаданными через API.
- Добавлены теги элементов и хостов, группы и выбранные поля inventory. Настройка и правила формирования лейблов описаны в [контракте метаданных](../metadata.md).
- Добавлена внутренняя телеметрия API/Streaming и готовый Grafana-дашборд; демонстрация проверяет доставку метрик и доступность дашборда.
- Добавлены примеры шардирования API и балансировки Streaming, нагрузочные сценарии и [руководство по масштабированию](../scaling.md).
- Исправлены раскрытие секретов URL в ошибках, обход лимита тела deflate и параллельный запуск API Pod при обычном rollout Kubernetes.
- Обновлены Collector/Contrib до v0.160.0 и стабильные модули Collector до v1.66.0. Минимальная версия Go для сборки — 1.26.8.
- CI и выпуск проверяют достижимые уязвимости; перед упаковкой проверяется каждый целевой бинарник.

## При обновлении с v0.1.0

Метаданные включены по умолчанию и добавляют лейблы: оцените изменение числа временных рядов. При необходимости отключите их через `metadata.enabled: false`.

API и Streaming используют разные имена и атрибуты метрик; переключение требует проверки запросов и дашбордов по [контракту конфигурации](../configuration.md). API-обогащение Streaming требует доступности Zabbix API и актуального снимка discovery.

Пример Kubernetes использует `Recreate`: обновление сопровождается перерывом сбора. Он не обеспечивает HA или fencing. Streaming не хранит очередь на диске; планируйте повторы на стороне отправителя.
