# v0.3.0 — единый формат метрик API и Streaming

## Изменения

- API и Streaming используют общий код нормализации, проверки чисел и времени, построения точек gauge и передачи следующему компоненту Collector.
- Имена метрик приводятся к lowercase snake_case, включая границы camelCase и аббревиатур. `%`, `°`, `+`, `&` заменяются словами `percent`, `degree`, `plus`, `and`; двоеточие, слеш и остальная пунктуация становятся разделителями `_`. Повторные разделители схлопываются, краевые удаляются.
- Генерируемые лейблы больше не получают префикс `zabbix_`. Ключи метаданных нормализуются без hex-кодирования `encoded_`. Одиночные значения передаются буквально, включая пустые строки, Unicode, `/var/log`, `https://host:443` и текст вида `["x"]`.
- Значения повторяющихся или совпадающих после нормализации ключей сортируются, очищаются от точных дубликатов и соединяются через `, `.
- Streaming с API-обогащением использует ключ элемента для имени метрики, как API. Без обогащения доступно только отображаемое название из payload; `hostid` и `item_key` отсутствуют.
- `NaN` и бесконечности отбрасываются в обоих режимах.
- Ошибки передачи downstream дают единый ERROR-лог. Произвольные тексты downstream-ошибок не копируются в логи и трассировки ресивера; исходная ошибка и её классификация сохраняются для программной обработки.
- Интеграционные тесты настоящего Collector проверяют Bearer-заголовок VM, ERROR-логи для 401/403, счётчики неудачных отправок и восстановление экспорта для API, Streaming и Streaming с API-обогащением, включая `batch` и очередь exporter.
- Обновлены документация, примеры конфигурации и демо-запросы.

## Переход с v0.2.0

**Меняются имена метрик и идентичность серий.** Обновите запросы, панели и оповещения перед переключением; ранее сохранённые серии автоматически не переименовываются.

| До | После |
| --- | --- |
| `zabbix_CPU_load` | `zabbix_cpu_load` |
| `zabbix_vfs_fs_size___free` | `zabbix_vfs_fs_size_free` |
| `zabbix_item_name` | `item_name` |
| `zabbix_item_tag_app="[\"api\",\"web\"]"` | `item_tag_app="api, web"` |

Отключение `metadata.enabled` не возвращает старые имена метрик. Настраиваемый `prom.prefix` применяется только к именам метрик и нормализуется вместе с ними. В примерах `configs/otelcol-streaming*.yaml` префикс теперь `zabbix_`, как в API; демонстрация сохраняет разные префиксы для параллельного сравнения режимов.

Читаемое объединение значений не является обратимым кодированием: литерал `api, web` неотличим от двух значений. Пустые лейблы exporter может опустить. Полные правила — в [контракте метаданных](../metadata.md).

Для VM с Bearer задайте отдельный заголовок `Authorization` у `prometheusremotewrite`. Уровня логов `info` достаточно для ERROR-диагностики 401/403. При `batch` или очереди успех receiver не подтверждает доставку в VM; контролируйте также `otelcol_exporter_send_failed_metric_points` и `otelcol_exporter_sent_metric_points`. Ответы 401/403 считаются постоянной ошибкой, потерянные точки после замены токена автоматически не догружаются. [Настройка и диагностика](../configuration.md#отправка-в-victoriametrics-и-ошибки-авторизации).
